# docs/migrations/admin-sql-allowlist.txt
# ─────────────────────────────────────────────────────────────────────────────
# Baseline allowlist for the Wave 22 Asset-Mutation Bypass Audit (PR-4).
# Enforced via `scripts/ci-bypass-audit.sh`, which re-runs the four rg queries
# from `docs/tmp/bypass_audit_<date>.txt` and fails on any non-allowlisted
# production hit.
#
# SCOPE
# ─────
# The `\.Upsert\(`, `UpsertClip\(`, `\.Restore\(`, `\.HardDelete\(` and
# `ExecContext.*media_assets` rg queries intentionally cast a WIDE net because
# the canonical `AssetMutationDispatcher` SSOT interface is the only sanctioned
# media_assets write surface for production code paths; every other direct
# mutation (regardless of destination table) is a regression because it
# bypasses (1) the atomic UPSERT + outbox event transaction, (2) the
# supersede-gate dedup, (3) the audit/projection trail.
#
# This file lists the LEGITIMATE non-dispatcher mutation entry points, grouped
# by reason. The CI gate parses every non-comment line as a repo-root-relative
# path, then `comm -13`'s the sorted rg hits against the sorted allowlist.
# Anything left over fails the gate with `exit 1`.
#
# POLICY (mirrors api-infrastructure-imports-allowlist.txt)
# ────────────────────────────────────────────────────────────
# * Each entry must ship with a migration plan tracked under the
#   corresponding `architecture/current.yaml` wave (or PR track for
#   in-flight work).
# * Adding a NEW entry REQUIRES team review (no solo adds); the entry
#   must carry an explicit bucket-reason header comment.
# * Removing an entry is always safe; the gate will fail if the underlying
#   `\.Upsert\( / UpsertClip\( / \.Restore\( / \.HardDelete\(` call is still
#   present, surfacing the regression for Wave 22 tasks 2/3/5.
#
# BASELINE RATCHET MODEL
# ───────────────────────
# Each entry below is grandfathered with its planned Wave 22 task. As tasks
# 2/3/5 land, the corresponding file path is REMOVED from this file in
# lockstep with the migration commit, so the gate tightens monotonically
# across the wave. This is the same ratchet mechanic used by
# `docs/migrations/api-infrastructure-imports-allowlist.txt` for the
# Wave-14 API-compaction grandfathered imports — the gate's "ZERO hits
# after allowlist exclusion" pass condition holds NOW and shrinks as the
# migration progresses.
# ─────────────────────────────────────────────────────────────────────────────
