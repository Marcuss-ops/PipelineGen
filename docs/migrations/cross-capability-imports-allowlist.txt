# docs/migrations/cross-capability-imports-allowlist.txt
# ─────────────────────────────────────────────────────────────────────────────
# Per-pair allowlist for Wave 19 PR4 (application/<capA>/ →
# application/<capB>/) hard gate.
#
# HOW THIS FILE WORKS
# ────────────────────
# scripts/archcheck/main.go::checkCrossCapabilityImport emits a distinct-
# pair set under Checks["cross_capability_import_pairs"] (one pair per
# <srcCap, importCap> combination where srcCap != importCap). Capability
# sets are filesystem-driven via `discoverApplicationCapabilities()`
# (`os.ReadDir("internal/application")` filtered to dirs not starting
# with `.` or `_`). The pair set is compared (subtractSet) against this
# allowlist. Any pair present in actual imports but NOT here is a
# regression; any allowlist entry that no longer maps to a current pair
# is a stale grandfathered entry. Both directions fail the gate.
#
# Same-capability imports are NOT captured (they are legal under any
# layout); same-capability is filtered out by the `srcCap == importCap`
# check in main.go, so entries of shape `<cap>-><cap>` would be no-ops
# if present.
#
# FORMAT
# ──────
# One pair per active line, exact shape `<srcCap>-><importCap>`
# (matches `pairSet[srcCap+"->"+importCap]` in main.go). Comment lines
# start with `#` and are ignored. Entries are sorted + deduped.
#
# POLICY
# ──────
# Adding a NEW entry REQUIRES operator review (no solo adds). Removing
# an entry is safe — the underlying cross-cap import will fail the gate
# as a `new cross_capability pair not in allowlist: <pair>` violation
# for action.
#
# CURRENT STATE — Wave 19 PR4 seed baseline (2026-06-26)
# ─────────────────────────────────────────────────────────────────────────────
# Baseline seeded from the canonical Go-side scan via `go run
# ./scripts/archcheck` and the Edges["cross_capability_import"] per-
# import graph; collapsed to distinct <srcCap>-><importCap> pairs using
# the same `capabilityOfFile` + `capabilityOfImport` rules as main.go.
#
# Operators remove entries as the underlying imports get lifted to typed
# ports, typed events, or composition-only bridges in `internal/app/`.
# The 15 live capability dirs at seed time are:
#
#   assets, books, channels, clips, generation, images, jobs, lessons,
#   mediasearch, middleware, scriptassets, scripts, system, voiceover,
#   youtube
#
# (Other historically-named capabilities — artlist, association,
# catalog, content, ingest, monitor, realtime, searchqueries — were
# collapsed into `assets`, `generation`, `scriptassets`, etc. by the
# Wave 14-18 PR-track migrations and are correctly filtered out by
# the `discoverApplicationCapabilities()` skip rule for `.`/`_`-
# prefixed AND non-directory entries.)
# ─────────────────────────────────────────────────────────────────────────────
assets->youtube
clips->assets
images->assets
mediasearch->assets
scriptassets->assets
scripts->assets
voiceover->assets
youtube->assets
