# docs/migrations/api-infrastructure-imports-allowlist.txt
# ─────────────────────────────────────────────────────────────────────────────
# Per-file allowlist for Check 19 of `scripts/ci-architectural-checks.sh`,
# promoted from soft-log to hard-fail evidence-based by commit
# `ci/archcheck-hard-fail` (June 2026).
#
# HOW THIS FILE WORKS
# ────────────────────
# Check 19 scans `internal/api/` (excluding `_test.go`) for any file whose
# source contains a real Go import of a package under
# `github.com/Marcuss-ops/PipelineGen/internal/infrastructure/`. The list of
# files that match is subtracted (via `comm -13`) against the paths listed
# below. Any leftover match fails the gate with `exit 1`.
#
# FORMAT
# ──────
# One repo-root-relative path per line. Comments start with `#` and are
# ignored. Groups of entries MAY be preceded by a section header comment
# (the header itself starts with `#` so the gate skips it).
#
# POLICY
# ──────
# * Each grand-parented import must ship with a migration plan tracked
#   under the corresponding `architecture/migration.yaml` wave (or PR
#   track for in-flight work).
# * Adding a NEW entry REQUIRES team review (no solo adds).
# * Removing an entry is always safe; the gate will fail if the underlying
#   import is still present, surfacing the regression for action.
#
# CURRENT STATE — Wave 14 grandfathered imports
# ──────────────────────────────────────────────
# The entries below are real Go imports of internal/infrastructure/*
# (verified via `rg -l 'github\.com/Marcuss-ops/PipelineGen/internal/infrastructure/'
# internal/api --glob '*.go' --glob '!*_test.go'`). The archcheck gate compares
# this file symmetrically with that scan, so stale entries fail too. They are grandfathered
# because Wave 14 (API compaction, June 2026) is in flight: the
# `internal/api/` subtree already dropped Drive, Realtime, SearchQueries,
# FullImages, Workers, and Sources — but the in-flight asset handlers
# (clips, artlist, youtube), the script orchestrator, and the channel/image
# middleware still legitimately need access to internal/infrastructure
# adapters for upload, Drive binding, and DB-backed policy checks.
#
# Migration plan (per PR3 docs/roadmap/PR3_API_COMPACTION.md):
#   * Wave 14-PR2: extract bulk_upload + handler.go + workers out of
#     api/assets/clips/* → internal/application/assets/clips/{service,worker}.
#     This removes 8 entries.
#   * Wave 14-PR3: extract api/script/{flow,handler_flow,handler_jobs,helpers}
#     → internal/application/scripts/{flow,service,worker} per docs/CHANGELOG_2026-06-03.md
#     §"ScriptFlow helper extraction".
#   * Wave 14-PR4: api/system/{handler,handler_drive,module} →

# Once the corresponding PR lands, the file path here MUST be REMOVED in
